## What can be independently reproduced

Anyone with AI agent session data (Claude Code JSONL, Codex JSONL, Cowork JSONL, or web chat JSON exports) can:

1. Run `tools/universal_error_scanner.py` on their own session data (produces `master_errors.csv`)
2. Run `tools/error_forensic_prep.py` on the output of step 1
3. Run `tools/error_root_cause_extractor.py` on the output of step 2
4. Apply the VERBATIM_FAILURE_CATALOGUE structural signatures to their own conversations
5. Use the ERROR_CAUSAL_CHAIN_DESIGN methodology to trace accountability
6. Use the REVERSE_CAUSAL_CHAIN_ANALYSIS technique on their own transcripts
7. Apply the DATA_DRIVEN_PREFLIGHT_CHECKLIST rules to their own code review

All steps are reproducible from this repo. Steps 1-3 require the user's own session data as input.

## Processing sequence

```
1. Collect session files (JSONL/JSON from agent platforms)
2. Run universal_error_scanner.py → master_errors.csv          [shipped]
3. Run error_forensic_prep.py → reviewable_errors.csv + cases  [shipped]
4. Run error_root_cause_extractor.py (reads reviewable_errors.csv) → root_causes + summary [shipped]
5. Review cases using ERROR_CAUSAL_CHAIN_DESIGN methodology    [shipped]
6. Document findings using VERBATIM_FAILURE_CATALOGUE format   [shipped]
7. Derive prevention rules using PREFLIGHT_CHECKLIST structure  [shipped]
```

Steps 3 and 4 form a true chain: Step 4 reads only the output of Step 3 (`reviewable_errors.csv`). Filtering is defined once in Step 3 and not duplicated.

## Known limitations

- Token waste calculations depend on `usage` fields in JSONL files. Web chat exports do not include token data. Platform-specific JSONL formats differ in token count location and structure.
- The behavioral waste estimate (15-20%) is derived from one conversation's block-by-block analysis. It is an estimate, not a corpus-wide measurement.
- Context overhead (~30%) is derived from one observed context breakdown. It varies by conversation length, tools loaded, and MCP connections.
- The 72%+ preventable rate applies to events that passed noise filters. The filters were developed iteratively; earlier versions produced different counts.
- The `TRANSCRIPT_ATOMIC_MAPPING.md` is interpretive synthesis, not deterministic extraction. It is clearly labeled as such.
